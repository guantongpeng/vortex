# P6.2 FP8(E4M3/E5M2)软件路径与量化 gate

## 目标

推进计划 P6-02:FP8 GEMM 的 kernel 侧(E4M3 与 E5M2 两种格式、FP32 累加),并把 MX/NVFP4/2:4 稀疏明确挂到上一节点落地的 `VX_CAPS_TCU_DTYPES` capability gate 上 —— 无 TCU 硬件配置时不假装支持。

## 交付物

- [`sw/dl/src/quant_fp8.h`](../../sw/dl/src/quant_fp8.h):E4M3(bias 7、无 inf、饱和 ±448)与 E5M2(IEEE inf/nan)的位级精确转换(RNE、次正规数、饱和/下溢、进位链),host/device 共用(与 fp16 同哲学:存储类型 + 显式转换,不用 `_Float8` 编译器类型)。
- `quant_gemm_fp8_kernel`:16×16 tile 形状,staging 时解码 FP8→FP32,内积与 FP32 GEMM 相同;per-tensor scale 的施加留给调用方(与计划 §10.2 的元数据职责一致)。`vx_quant_gemm_fp8(mode=0|1)`。
- 测试并入 `tests/dl/quant`:host 用**同一头文件**量化,参考 = 量化值 double 累计 —— 这同时验证了转换函数的往返正确性。

## Capability gate 状态(P6-02 剩余项)

`VX_CAPS_TCU_DTYPES` 已可查询(默认配置 = FP16 位)。MXFP8/MXFP4、NVFP4、2:4 稀疏需要:
1. TCU 配置构建树(`-DVX_CFG_EXT_TCU_ENABLE` + 对应 dtype 宏)——构建脚本就绪,数值 golden 未建;
2. 独立 kernel + 模型精度报告后才允许进入 capability(计划 §10.1 Q4/Q5 的前置),**本节点不启用这些位**。

FP8 的硬件 TCU 变体(替代软件 kernel)同样等 TCU 树;签名已按可替换设计。
